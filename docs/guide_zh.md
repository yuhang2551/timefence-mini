# 读懂 TimeFence

这份指南的目标：读完你能自己讲清楚这个项目做了什么、为什么这样设计、结果怎么看，面试被追问也能接得住。不需要会手写这些代码，但要知道每块在干什么、彼此怎么连。

建议顺序：先读第 1、2 节（概念），再按第 3 节的顺序打开代码，每一步跑一下对应的命令。

## 1 一分钟版本

> 我做了一个 A 股因子挖掘的多智能体系统。三个 LLM 角色分工：规划 Agent 决定每轮研究什么方向，研究 Agent 把想法写成因子表达式，评审 Agent 总结经验写进记忆。因子收不收由代码里的统计规则决定，不由模型决定。整个系统的核心约束是"看不到未来"：数据带公开时间，策略只能通过时间围栏取数，Agent 只拿得到训练集，并且用"删掉未来数据重算、结果必须完全一致"的测试来证明。挖出来的因子在验证集确认方向，在测试集上按 A 股规则（T+1、涨跌停、整手、印花税）回测一次，和随机搜索、经典因子两个基线比。

## 2 需要的量化概念（只讲用到的）

**因子**：给每只股票每天打一个分的公式。比如"过去 5 天涨得越多，分越低"（`-ts_sum(returns, 5)`，短期反转）。好的因子，分高的股票之后平均涨得更多。

**截面 / 时间序列**：截面是"同一天、不同股票之间比"（`rank`、`zscore`），时间序列是"同一只股票、和自己的过去比"（`ts_mean`、`delay`）。

**IC 和 RankIC**：某一天，因子值和"之后 5 天的收益"的相关系数叫 IC；先把两者都换成排名再算相关，叫 RankIC（不怕极端值，更常用）。每 5 天算一次，取平均。A 股日频因子的 RankIC 有 0.03 就算不错，0.05 以上算强。

**ICIR**：RankIC 的均值除以它的标准差，衡量"稳不稳"。均值高但忽正忽负的因子，ICIR 低。

**分组收益（五分位）**：每期按因子值把股票分成 5 组，看每组之后的平均收益。好因子从低组到高组大致单调递增。"多空收益"是最高组减最低组。

**换手**：每期头部那一组有多少股票换掉了。换手高意味着交易多、成本高，A 股卖出要交印花税，换手对收益影响很大。

**未来函数（look-ahead bias）**：用了决策时刻还不知道的数据。比如用今天的收盘价决定今天开盘买什么。回测会好得离谱，实盘完全不行。这是本项目最核心要防的东西。

**幸存者偏差**：只用今天还活着的股票回测，等于提前排除了后来退市的"坏学生"，回测会偏乐观。本项目保留退市股，股票池每天按当时的成交额选。

**过拟合 / 多重检验**：试的公式越多，越容易碰到"历史上碰巧好用"的。所以要分训练集、验证集、测试集，测试集只用一次，并且记录一共试了多少个。

**A 股规则**：T+1（今天买的明天才能卖）；涨跌停（主板 ±10%，创业板 2020-08-24 起 ±20%，科创板 ±20%），开盘就涨停一般买不到；100 股一手；佣金最低 5 元；卖出印花税 2023-08-28 从 0.1% 降到 0.05%。

**复权**：分红送股那天股价会"跳水"，但持有人没亏。复权因子把历史价格调成连续的。因子用复权价，券商成交用真实价格。

## 3 按这个顺序读代码

每一步：打开哪个文件、它回答什么问题、跑什么命令看效果。

### 第 1 步：数据长什么样（`data/schema.py`、`data/store.py`）

- 问题：数据怎么存？为什么每条都有 `available_at`？
- 看点：`BAR_COLUMNS` 是长表（一行一只股票一天），`MarketStore.panel("close")` 把它变成宽表（行是日期、列是股票）。`close` 是复权价，`raw_close` 是真实价。
- 动手：`uv run timefence data synth --out data/synth`，再用 Python 读一下 `MarketStore.load("data/synth").panel("close")`。

### 第 2 步：时间围栏（`data/fenced.py`、`core/clock.py`）

- 问题：策略怎么保证拿不到未来？
- 看点：`FencedData.panel()` 先按 `as_of` 切，再 `_check` 一遍；`stocks` 去掉了名称，退市日期只在退市后可见。
- 动手：读 `tests/test_fence.py::test_late_published_data_raises`，它故意造了一条"第二天早上才公布"的数据，看围栏怎么抓到它。

### 第 3 步：股票池（`data/universe.py`）

- 问题：为什么不用沪深 300 成分股？
- 看点：每天只用过去 20 天的成交额排名，上市不满一年的不要。拿不到历史成分股，用今天的成分股会有幸存者偏差。

### 第 4 步：因子语言（`factors/dsl.py`、`factors/ops.py`）

- 问题：为什么不让模型直接写 Python？怎么保证公式不偷看未来？
- 看点：`_Checker.visit` 逐个节点检查；`OPS` 是全部允许的算子；没有任何"往前移"的算子。截面算子只在股票池内比较。
- 动手：`uv run pytest tests/test_dsl.py -v`，看哪些写法会被拒绝、报什么错。

### 第 5 步：因子打分（`factors/evaluate.py`）

- 问题：怎么判断一个因子好不好？
- 看点：`forward_open_returns` 是标签（t+1 开盘买、t+1+h 开盘卖），只有这里用它；`sample_dates` 每 h 天取一次、末尾 h+1 天不用；`AcceptanceRules` 是入库标准。
- 动手：读 `tests/test_evaluate.py::test_planted_reversal_is_found`，模拟数据里埋了反转规律，打分能把它找出来；没埋规律时就找不到。

### 第 6 步：回测（`backtest/`）

- 问题：怎么模拟真实交易？
- 看点：`engine.run_backtest` 的循环：收盘后决策，第二天开盘成交，收盘估值；`broker.Broker.buy/sell` 里依次检查停牌、涨跌停、T+1、整手、现金；`rules.py` 和 `costs.py` 是规则和费用。
- 动手：`uv run pytest tests/test_backtest.py -v`，每个测试名就是一条规则。

### 第 7 步：策略（`strategy/`）

- 问题：多个因子怎么合成一个决定？
- 看点：`FactorModel.score` 把每个因子在股票池内标准化、按训练集方向加权平均；`TopKStrategy` 选前 K 只等权，已经持有的只要还在前 1.5K 就不卖（减少换手）。

### 第 8 步：Agent（`agents/`）

- 问题：三个 Agent 怎么协作？模型和代码各负责什么？
- 看点：`graph.py` 顶部的流程图；`tools.FactorLab.judge` 是"代码负责判"的地方，它的构造函数拒绝含未来数据的输入；`memory.py` 的 `digest` 是每轮给模型看的摘要；`prompts.py` 是三个提示词；`llm.py` 的缓存和预算。
- 动手：跑一次离线演示，然后打开 `runs/<名字>/transcript.jsonl`，一行一次模型调用，能看到它每轮看到了什么、回了什么。

### 第 9 步：实验流程（`experiments/runner.py`）

- 问题：训练、验证、测试怎么串起来？
- 看点：`_mine` 只用训练集；`_validate` 和 `_test` 在挖掘结束之后才运行；测试只跑一次；`baselines.py` 用同一个 `FactorLab` 跑随机和人工因子，保证比较公平。

## 4 跑一遍演示，读懂报告

```bash
uv run timefence data synth --out data/synth
uv run timefence run --data data/synth --out runs/demo --method agent --offline --top-n 150 --top-k 20
```

打开 `runs/demo/report.md`：

1. 开头的警告：模拟数据、离线替身，数字不算结果。
2. "挖掘过程"：试了多少个、通过多少、为什么没通过（详细原因在 `memory.sqlite` 里）。
3. "因子库"：每个因子在训练、验证、测试上的 RankIC 和 ICIR。正常情况是训练最好、之后衰减；如果测试集反而远好于训练集，要怀疑哪里有问题。
4. "组合回测"：重点看年化超额、信息比率、超额最大回撤、年换手和年交易成本。

## 5 自己改一处（理解得最快的方法）

让 AI 帮你做下面任意一个，然后跑测试看哪里变了：

1. 加一个算子 `ts_skew(x, d)`（滚动偏度），登记到 `OPS`。`tests/test_ops.py` 会自动检查它没有偷看未来。
2. 把验收规则的 |RankIC| 门槛从 0.02 提到 0.03，重跑演示，看通过数量和测试集表现怎么变。
3. 加一个"过拟合审查"角色：在 review 之前，让模型指出本轮哪些因子可能是数据挖掘的巧合。改 `prompts.py` 和 `graph.py`，用 `ScriptedLLM` 写一个测试。

## 6 面试怎么讲

按"问题 → 设计 → 证据"的顺序讲：

1. 问题：LLM 挖因子很容易被未来信息污染，也很容易过拟合。
2. 设计：时间围栏 + 白名单语言 + Agent 只看训练集 + 规则在代码里 + 训练/验证/测试分开、测试只跑一次。
3. 证据：截断等价测试、`timefence audit` 在真实数据上的结果、和两个基线的对比表、留出期的表现。
