# ADR 0001：用"时间围栏"在框架层面防止偷看未来

- 状态：已采纳
- 日期：2026-10-13

## 背景

回测里最常见、也最难发现的错误是用了决策时刻还不知道的数据（look-ahead bias）。它会让回测结果看起来很好，实盘却完全不行。LLM Agent 让这个问题更难：Agent 写的代码和调用的工具都可能在不经意间读到未来，而且很难逐行审查。

只在提示词里写"不要用未来数据"没有用：模型不一定遵守，就算遵守了，它调用的工具也可能出错。

## 决定

把"不用未来数据"做成数据层的结构，而不是靠约定：

1. 每条数据带 `available_at`（日线是当天 15:00），表示它什么时候公开。
2. 策略只能拿到 `FencedData(store, as_of)`：所有查询先按 `as_of` 切，再检查一遍有没有 `available_at > as_of` 的数据，有就抛 `LeakError`。
3. 时钟由回测框架推进，策略和 Agent 改不了"今天"。
4. 用**截断等价测试**兜底：把某天之后的数据删掉重算，因子值必须完全一样。这个测试对随机生成的表达式反复跑，真实数据上用 `timefence audit` 跑。
5. 股票表也过一道围栏：不给名称（名称是今天的，可能带 *ST），退市日期只在退市之后才可见。

## 为什么"切"之后还要"查"

切是主要手段，查是第二道防线。如果哪天有人改了存储或者切的逻辑写错了，查能把一个"悄悄变好的回测"变成一个"马上报错的程序"。在测试里我们故意造一条"第二天早上才公布"的数据，确认它会触发 `LeakError`。

## 代价

- 每次查询多一次检查，开销很小（按日期预先算好每天最晚的 `available_at`）。
- 策略不能随手拿全量数据，需要声明自己要多长的历史（`lookback`）。这反而让策略的数据需求变得明确。

## 以后

加入财报等低频数据时，`available_at` 用公告日而不是报告期，围栏代码不用改。
