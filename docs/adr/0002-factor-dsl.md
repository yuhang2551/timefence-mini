# ADR 0002：因子用白名单表达式语言，不让模型直接写 Python

- 状态：已采纳
- 日期：2026-10-13

## 背景

让 LLM 写因子有两种做法：直接写 Python/pandas 代码，或者写一种受限的表达式语言（DSL）。

## 决定

用 DSL。语法借用 Python 表达式（用 `ast` 解析），但逐个节点检查，只放行：

- 8 个数据字段：`open high low close volume amount vwap returns`
- 21 个算子：时间序列类（`ts_mean`、`delay`、`ts_corr` 等）、截面类（`rank`、`zscore`）、逐元素类（`abs`、`log` 等）
- 加减乘除和数字常量

另外规定：窗口必须是 1 到 250 之间的整数常量；表达式最多 40 个节点、7 层；需要的历史不超过 300 天；不能除以 0 常量；不能有关键字参数、属性访问、下标、lambda、条件表达式、乘方。

## 为什么

1. **不可能偷看未来**：语言里没有"往前移"的算子（没有 lead，没有负的 delay），每个时间序列算子都只看过去（有测试逐个检查），所以任何合法表达式都不会用到未来。Python 代码做不到这种保证。
2. **安全**：不执行任意代码，不需要沙箱。
3. **好去重**：解析后转成规范形式（`ast.unparse`），写法不同但实质相同的表达式（多空格、多括号）会被认出来。
4. **错误信息能直接反馈给模型**：比如"window 0 outside 1..250"，模型下一轮就能改。
5. **便于比较**：随机搜索基线和 Agent 用同一种语言，公平。

## 代价

表达能力有限，比如写不出条件逻辑、行业中性化。需要时加算子（每个新算子必须通过"改未来不影响过去"测试）。

## 截面算子只在股票池内比较

`rank`、`zscore` 只在当天的股票池里比较。否则，面板里多一只"几年后才变活跃"的股票，就会改变今天别的股票的排名，这是一种很隐蔽的未来信息。
