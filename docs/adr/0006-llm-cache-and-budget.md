# ADR 0006：模型调用走缓存和预算，提示词要求 JSON

- 状态：已采纳
- 日期：2026-10-13

## 决定

1. **只用兼容 OpenAI 协议的接口**，模型名、地址、密钥环境变量都可以从命令行换。没有用 LangChain 的模型封装，少一层依赖，行为更透明。（2026-10 起 Claude 例外，见第 9 条。）
2. **磁盘缓存**：请求内容（模型、消息、温度）的哈希作为键，回复存成 JSON。重跑同一个实验时直接读缓存：不花钱，结果完全一样。
3. **预算**：每次运行限制调用次数和 token 数，超了就停在当前轮，已经做完的工作都在研究记忆里，不会丢。
4. **要求 JSON 输出**（`response_format=json_object`），解析失败时当作"没有提案"处理，走重试，不会让流程崩掉。
5. **完整记录**：每次调用的输入输出写进 `transcript.jsonl`，方便事后看模型是怎么想的。
6. **密钥只从环境变量读**（命令行启动时会把本地 `.env` 读进环境变量，`.env` 不提交），代码、提交的配置、日志里都不出现。仓库里的 `.env.example` 只列出变量名，值留空；key 没填（或还是旧版本的占位符）时，Agent 运行在开始前就报错。
7. **离线替身**（`--offline`）：不调模型，按模板生成表达式，让整个流程不联网也能跑；报告里会标明"不是大模型"。测试里用 `ScriptedLLM` 精确控制模型的回复。
8. **思考模式默认关闭**（2026-10 补充）：DeepSeek 在 2026-07-24 停用了 `deepseek-chat` 等旧模型名，新模型默认打开思考模式。这里默认用 `deepseek-flash` 并显式关闭思考模式（`--thinking disabled`），和原来的非思考模式一致：温度参数生效，速度快，成本低。打开时（`--thinking enabled`）不再请求 JSON 模式（官方不建议两者同时开），仍然只从最终回复 `content` 里解析 JSON，推理过程 `reasoning_content` 不当结果用。思考模式开关算在请求内容里，两种模式的缓存互不混用。新模型的知识截止也更晚（V4-Flash 据报到 2025-05，`deepseek-flash` 背后的 V4.1-Flash 没有公布），所以留出期默认起点从 2025-01-01 改为 2026-01-01。（默认服务商和这个固定日期都已被第 9 条取代。）
9. **服务商可切换，留出期跟着模型走**（2026-10 补充）：`--provider` 选 `claude`（默认）、`k2`（MBZUAI 基础模型研究院的 K2 Horizon）或 `deepseek`，每个服务商在 `agents/llm.py` 的 `PROVIDERS` 里登记默认模型（以及知识截止相同的其他模型）、地址、key 的环境变量和知识边界。Claude 默认用最便宜的 Claude Haiku 5.5，Claude Opus 5.5 知识截止相同，也登记在内。K2 Horizon 和 DeepSeek 走兼容 OpenAI 协议的接口。K2 Horizon 默认走 IFM 自己的接口（`https://api.ifm.ai/v1`），换其他服务商时地址从 `K2_BASE_URL` 读，接口里的模型名不同就从 `K2_MODEL` 读（算同一个模型，知识边界不变）；它总是先推理，推理深度通过聊天模板参数 `reasoning_effort` 传，采样参数按模型说明固定（temperature 1.0、top_p 0.95、至少 32,768 个输出 token），不用调用方的温度，也不请求 JSON 模式；如果服务端没有把推理和回答分开，解析时跳过 `</think>` 之前的内容。Claude 走官方 Anthropic SDK：它总是先思考，用 `effort` 调深度，不发温度；没有 JSON 模式参数，靠提示词要求 JSON，解析时容忍代码块；系统提示词每轮相同，标记为提示词缓存；回复用流式接收，避免长回复超时；遇到安全拒答时由服务端换更早的 Claude 模型重试，更早的模型知识不会更新，留出期仍然成立；Claude Haiku 5.5 没有这种服务端重试，请求里就不带这个参数，拒答按空回复处理。知识边界是模型可能知道的最后一天的下一天：公布了知识截止的取截止日的下一天，没公布的取发布日。留出期默认从这一天开始；用的不是登记过的模型时，必须用 `--holdout-start` 指定起点，否则报错。

## 为什么不用函数调用（tool calling）

这个流程里模型只需要"给出几个表达式和理由"，工具（打分、验收）由流程本身调用，不需要模型决定什么时候调。用 JSON 输出更简单，换模型也更容易。
