# ADR 0003：Agent 只看训练集，验收规则写在代码里

- 状态：已采纳
- 日期：2026-10-13

## 背景

因子挖掘最大的风险是过拟合：试的表达式越多，越容易碰到"在历史上碰巧好用"的公式。如果 Agent 还能看到验证集或测试集的结果，它会不自觉地往那边优化，样本外检验就失效了。

## 决定

1. **物理隔离**：Agent 用的数据对象由 `store.slice_until(训练集结束日)` 构建，里面根本没有之后的数据。`FactorLab` 构造时检查这一点，不满足就抛 `LeakError`。
2. **只回传训练集指标**：Agent 看到的只有训练集上的 RankIC、ICIR、分组收益、换手、相关性。
3. **验收规则在代码里**（`AcceptanceRules`）：覆盖率 ≥ 60%，|RankIC| ≥ 0.02，|ICIR| ≥ 0.15，方向一致的期数 ≥ 55%，和已收因子的相关性 ≤ 0.7，头部五分位换手 ≤ 90%。模型说得再有道理，过不了规则就进不了库。
4. **验证和测试在挖掘结束之后**，由 `experiments/runner.py` 做；测试只跑一次。
5. **全部试验都记下来**（SQLite），包括失败的。报告里写明试了多少个，用来解释样本外为什么会衰减。
6. **打分期去重叠**：每 h 天打一次分，窗口末尾 h+1 天不打分，避免标签跨进下一个时间段。

## 为什么不让模型来判断收不收

模型的判断不稳定，也可能被它自己写的理由说服。确定性规则可复现、可测试、可解释。模型负责"想"，代码负责"判"。

## 剩下的风险

LLM 的训练数据里有历史行情和研究报告，它可能"记得"某段时间什么因子好用。这个没法在代码里隔离，所以最后一道检验放在模型知识截止之后的留出期（2025 年起），见 `--holdout`。
